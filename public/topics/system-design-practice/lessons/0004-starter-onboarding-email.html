1Clarifique (2 min)Clarify (2 min)

  • Rascunho? o usuário pode salvar e voltar depois? (se sim, estado “incompleto” no banco).Draft? can the user save and come back? (if yes, an “incomplete” state in the DB).
  • Validação: email único? senha forte? (índice único no email).Validation: unique email? strong password? (unique index on email).
  • Email: tem que chegar “agora” ou pode demorar alguns segundos? (pode demorar → assíncrono).Email: must arrive “now” or can it take a few seconds? (can delay → async).
  • Volume: 100 cadastros/dia? 100k? (muda se precisa de fila).Volume: 100 signups/day? 100k? (changes whether you need a queue).

3Desenhe (5 min) — a parte assíncrona é o pontoDraw (5 min) — the async part is the point

Narração-chave (a parte que decide a vaga): “A API grava o usuário e publica o email numa fila, sem esperar. Um worker pega da fila e chama o serviço de email. Assim o cadastro responde rápido mesmo se o email demorar — e se o email falhar, a fila reenvia.”Key narration (the part that decides the hire): “The API stores the user and publishes the email to a queue, without waiting. A worker pulls from the queue and calls the email service. So signup responds fast even if email is slow — and if email fails, the queue retries.”

Armadilha clássica (não caia): chamar o serviço de email síncrono dentro do request. Se o SES cair, o cadastro inteiro falha por causa do email. Async desacopla.Classic trap (don't fall): calling the email service synchronously inside the request. If SES is down, the whole signup fails because of email. Async decouples it.

  • Email assíncrono via fila (SQS/Redis/queue nativa do serverless) → cadastro rápido, retry automático.Async email via a queue (SQS/Redis/native serverless queue) → fast signup, automatic retry.
  • Idempotência: token de uso único; used=true depois do clique; expiração (ex.: 24h).Idempotency: single-use token; used=true after click; expiry (e.g. 24h).
  • Falhas: email service fora (fila + retry), token expirado (regera), duplo submit (índice único + idempotência).Failures: email service down (queue + retry), expired token (regenerate), double submit (unique index + idempotency).
