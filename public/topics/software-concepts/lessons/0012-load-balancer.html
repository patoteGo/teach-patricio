Um servidor cai. Ninguém percebe. Esse é o trabalho dele.One server dies. Nobody notices. That's its whole job.

Na lição de estimativa você calculou QPS de pico. O load balancer é o que faz o pico caber: um porteiro na frente de N servidores que recebe toda a fila e distribui — sem os clientes saberem quantos servidores existem.In the estimation lesson you computed peak QPS. The load balancer is what makes the peak fit: a doorman in front of N servers who takes the whole line and spreads it — clients never learn how many servers exist.

1O modelo mental (3 cartões)The mental model (3 cards)

Um endereço, N máquinasOne address, N machines

O cliente conhece um IP só — o do load balancer. Atrás dele vivem servidores intercambiáveis que nem precisam de IP público. Escalar = adicionar servidor; ninguém reconfigura cliente.The client knows one IP only — the balancer's. Behind it live interchangeable servers that don't even need public IPs. Scaling = add a server; no client gets reconfigured.

Só manda pra quem está vivoOnly routes to the living

O balancer faz health checks periódicos (GET /health). Servidor que falha sai da rotação na hora, sem humano — e volta sozinho quando responde de novo.The balancer runs periodic health checks (GET /health). A failing server leaves the rotation immediately, no human involved — and returns by itself once it answers again.

Espera-less: sem estadoStateless by design

O balancer só distribui bem se os servidores forem intercambiáveis: qualquer um pode atender qualquer pedido. Sessão no servidor quebra isso — a sessão precisa ir pra Redis ou banco.Balancing only works when servers are interchangeable: any one can serve any request. Server-local session state breaks that — sessions belong in Redis or the database.

2A viagem de um pedido (e a morte de um servidor)One request's trip (and one server's death)

1
GET /api/orders → IP do balancer

O DNS resolve o nome para o IP do balancer. O cliente acha que é ele o servidor. Ele nunca soube quantos existem.DNS resolves the name to the balancer's IP. The client thinks that IS the server. It never learns how many exist.

2
Health check: servidor 3 está mortoHealth check: server 3 is dead

O balancer pergunta /health a cada servidor de N em N segundos. O 3 falhou duas vezes seguidas → sai da rotação. Nenhum pedido vai mais pra lá.The balancer asks /health every few seconds. Server 3 failed twice in a row → out of the rotation. No request goes there anymore.

3
Escolhe um vivo e repassaPicks a live one and forwards

Entre os vivos, uma regra decide: round-robin (fila circular), least connections (menos ocupado), ou hash do cliente. O pedido sai com o IP de origem trocado — NAT simples.Among the living, a rule decides: round-robin (circular line), least connections (least busy), or client hash. The request is forwarded with its source IP rewritten — plain NAT.

4
Resposta volta pelo mesmo caminhoResponse returns the same way

O servidor responde ao balancer, que devolve ao cliente. O 3 pode reiniciar, passar no health check e voltar à rotação — o cliente nunca soube da festa.The server answers the balancer, which answers the client. Server 3 can reboot, pass its health check, and rejoin — the client never knew there was a party.

4Camada 4 vs camada 7 — e o calcanhar de aquilesLayer 4 vs layer 7 — and the Achilles heel

L4 olha só IP/porta (pacote): rápido, burro — não lê o HTTP. L7 lê a requisição: rota por path (/api pros servidores de API, /img pro CDN), termina o TLS, reescreve headers. A regra prática: L4 quando só falta dividir; L7 quando a decisão depende do conteúdo.L4 looks at IP/port only (packets): fast, dumb — never reads HTTP. L7 reads the request: routes by path (/api to API servers, /img to the CDN), terminates TLS, rewrites headers. Rule of thumb: L4 when you only need to split; L7 when the decision depends on content.

O calcanhar: quem balanceia o balancer? Ele é um ponto único de falha — a menos que você o resolva: dois balancers com IP virtual (VRRP) — um ativo, um à espera que assume em segundos — ou DNS com múltiplos IPs. No mundo real isso tem nome de produto: AWS NLB/ALB, GCP LB, nginx, HAProxy.The heel: who balances the balancer? It's a single point of failure — unless you solve that too: two balancers sharing a virtual IP (VRRP) — one active, one on standby taking over in seconds — or DNS with multiple IPs. In practice these are products: AWS NLB/ALB, GCP LB, nginx, HAProxy.

Segundo susto: health check mentiroso. Se o check é GET / mas o banco do servidor caiu, a página responde 200 e o balancer segue mandando tráfego pra um servidor que falha em tudo. O check tem que testar o que importa: dependências inclusas.Second scare: the lying health check. If the check is GET / but the server's database died, the page still returns 200 and the balancer keeps sending traffic to a server that fails everything. The check must test what matters: dependencies included.

O load balancer também é um amortecedor de pico. Com o cache ele é a dupla de escala horizontal: o cache corta trabalho, o balancer distribui o que sobra por mais máquinas. Juntos transformam "um servidor grande" em "N servidores pequenos".The load balancer is also a peak absorber. With the cache it forms the horizontal-scaling pair: the cache cuts work, the balancer spreads what's left across more machines. Together they turn "one big server" into "N small servers".

# nginx: L7 por trás, health check ativo
upstream api {
    server 10.0.1.10:3000;
    server 10.0.1.11:3000;
    server 10.0.1.12:3000 backup;   # entra só se os dois caírem
}

server {
    location /api {
        proxy_pass http://api;      # round-robin é o padrão
    }
    location /health { return 200; }
}

Frase que fecha a questão: "O load balancer é o porteiro: um IP público, N servidores intercambiáveis atrás. Health check tira o morto da rotação em segundos; a regra de distribuição — round-robin, least connections ou hash — divide a fila. L4 divide pacotes, L7 entende HTTP e roteia por conteúdo. Estado vai pra Redis/banco, nunca pro servidor. E o próprio balancer nunca é único: par com IP virtual ou DNS multi-IP."The sentence that closes the question: "The load balancer is the doorman: one public IP, N interchangeable servers behind it. Health checks drop the dead from rotation in seconds; the distribution rule — round-robin, least connections, or hash — splits the line. L4 splits packets, L7 reads HTTP and routes by content. State goes to Redis/the database, never the server. And the balancer itself is never singular: a pair with a virtual IP or multi-IP DNS."
