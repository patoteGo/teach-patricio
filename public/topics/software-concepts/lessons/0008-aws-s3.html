S3 não é um disco. É um mapa gigante chave → bytes que nunca se perde.S3 isn't a hard drive. It's a giant key → bytes map that never gets lost.

O SQS guardava mensagens curtas; o S3 guarda os bytes do sistema: fotos, backups, logs, sites inteiros. Objeto de até 5 TB, durabilidade de 11 noves — e uma regra: aqui, a chave é tudo.SQS stored short messages; S3 stores the system's bytes: photos, backups, logs, entire websites. Objects up to 5 TB, 11-nines durability — and one rule: here, the key is everything.

1O problema que o S3 resolveThe problem S3 solves

Disco de servidor é frágil e limitado: enche, morre, e não cresce sozinho. O S3 é armazenamento de objetos: você entrega bytes e uma chave, a AWS replica em várias zonas de disponibilidade, e o armazenamento total é ilimitado — não existe “cheio”.Server disks are fragile and finite: they fill up, they die, they don't grow on their own. S3 is object storage: you hand over bytes and a key, AWS replicates across availability zones, and total storage is unlimited — “full” doesn't exist.

Dois vocábulos e pronto: bucket (o contêiner, nome global único, criado numa região) e objeto (a chave + os bytes + metadados, de 0 a 5 TB).Two words and done: bucket (the container, globally unique name, created in one region) and object (the key + the bytes + metadata, 0 to 5 TB).

S3 = mapa chave → bytes. Busca pela chave exata é instantânea; qualquer coisa além disso (listar, buscar, filtrar) é outro serviço, não é para o S3.S3 = key → bytes map. Lookup by exact key is instant; anything beyond that (list, search, filter) is another service's job, not S3's.

3O detalhe que todo mundo erra: consistência e os 11 novesThe detail everyone misses: consistency and the 11 nines

Resposta antiga de entrevista: “S3 é eventualmente consistente — um GET logo após o PUT pode retornar 404”. Errado desde dezembro de 2020: o S3 hoje tem strong read-after-write consistency — PUT e o GET imediato retornam o objeto novo, ponto.Old interview answer: “S3 is eventually consistent — a GET right after a PUT may 404”. Wrong since December 2020: S3 now has strong read-after-write consistency — PUT then immediate GET returns the new object, period.

E os 11 noves de durabilidade (99,999999999%): guarde 10 milhões de objetos e espere perder 1 a cada 10 mil anos. Mas durabilidade ≠ disponibilidade — o objeto existe, embora o serviço possa estar indisponível ~53 min/ano (99,99%).And the 11 nines of durability (99.999999999%): store 10 million objects and expect to lose 1 every 10,000 years. But durability ≠ availability — the object exists even while the service may be down ~53 min/year (99.99%).

S3 não é banco de dados. Se você precisa listar, filtrar ou consultar metadados no hot path, guarde os metadados num banco (DynamoDB, Postgres) e busque o objeto no S3 pela chave exata.S3 is not a database. If you need to list, filter, or query metadata on the hot path, keep metadata in a database (DynamoDB, Postgres) and fetch the S3 object by exact key.
