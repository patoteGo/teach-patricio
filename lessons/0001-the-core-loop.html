⬡ Lesson 01 · Foundations

Pi is a loop,
not a chat box.

Before any power move, lock in the one mental model that makes every feature click: what Pi actually is, the four tools it hands the model, and the turn that repeats until your job is done.

↑ Part of the Pi Power-User course · next: Driving the TUI

1What Pi actually is

One sentence to anchor everything: Pi is a minimal terminal harness that loops a model over a handful of file-and-shell tools. It is deliberately not an IDE, not an agent framework, not a chat app.

Source: Pi docs — Overview · "By default, pi gives the model four tools: read, write, edit, and bash."

The reframe: Pi is the host. The model is the brain, the four tools are its hands, the session JSONL is its memory. Pi itself owns almost no features on purpose — you bolt those on. Everything "missing" (sub-agents, plan mode, permissions…) is a choice, not an oversight.

2The four default tools

These four are always on. Pi has three more available (grep, find, ls) that you opt into — but the model's whole world starts here.

R

read

Read a file (text or image). The model's eyes. Truncated to keep context lean.

read(path)
W

write

Create or overwrite a file wholesale. New files or full rewrites.

write(path, content)
E

edit

Surgical text replacement — multiple exact swaps in one call. The diff engine.

edit(path, edits[])
$

bash

Run any shell command. Test, build, grep, git — full system access.

bash(command)

Source: Pi CLI Reference · built-in tools: read bash edit write grep find ls · scope with --tools / --exclude-tools.

3The turn loop

This is the single most important picture in the whole course. A turn is "model reasons → maybe calls tools → sees results → reasons again". The loop repeats until the model stops calling tools and replies.

  1. You prompt. Type a request + optional @file refs. → before_agent_start
  2. Model reasons. It thinks (the collapsible thinking block) and emits a response — either text, or tool calls.
  3. It calls tools. e.g. read three files, then bash npm test. → tool_call
  4. Pi runs them. The harness executes each call and feeds results back — not the model's runtime, Pi's.
  5. Results return. The loop jumps to step 2 with new context. Repeat until the model replies in plain text. → turn_end / agent_settled

Power insight: while the loop runs you are not stuck waiting. Press Enter to queue a steering message (delivered after the current tool batch) or Alt+Enter for a follow-up (delivered after all work finishes). You steer a live loop — you don't block it.

Sources: Interactive mode · Message Queue · extension event lifecycle in docs/extensions.md.

4Anatomy of one turn

A real exchange, annotated. Watch the loop fire twice before the model is done. 

# 1 ── you prompt ──────────────────────────────────────────
> "Add a health check endpoint and make sure tests pass"

# 2 ── turn 1: model reasons, calls tools ──────────────────
🧠 thinking: (collapsible) I'll look at the existing routes…
🔧 read  src/server.ts
🔧 read  src/routes.ts
🔧 bash  npm test 2>&1 | tail -20

# 4/5 ── Pi runs them, results flow back into context ─────
✓ server.ts: 142 lines · routes.ts: 88 lines
✓ tests: 47 passed

# 2 ── turn 2: model reasons again with that new context ──
🧠 thinking: add GET /health, return 200…
🔧 edit  src/routes.ts   (insert handler)
🔧 bash  npm test
✓ tests: 48 passed

# loop ends ── model replies in plain text ───────────────
💬 Done. Added GET /health → 200 OK; suite is green (48/48).

The number that matters: each 🔧 is a round-trip that consumes context + tokens. Long sessions fill the window — that's exactly what compaction (a later lesson) exists to manage. The whole loop is logged to one branching JSONL file you can rewind anytime with /tree.

5What Pi deliberately omits

Reading this grid is what turns "why doesn't Pi have X?" into "ah, X is a choice I make." Every crossed-out item has an explicit Pi-native alternative.

🚫 No MCP servers

Build a CLI tool with a README (a skill), or add MCP via an extension.

🚫 No sub-agents

Spawn Pi instances in tmux, build your own with extensions, or install a package.

🚫 No permission popups

Run in a container, or build a confirmation flow with an extension.

🚫 No plan mode · no to-dos

Write plans/TODOs to a file — or, again, an extension.

🚫 No background bash

Use tmux. Full observability, direct interaction, no magic.

✅ Instead, four primitives

Skills · Extensions · Prompt Templates · Packages — the entire power-user surface. That's the rest of this course.

Source: Mario Zechner — "Pi Coding Agent" (design rationale) · also "What if you don't need MCP at all?"
