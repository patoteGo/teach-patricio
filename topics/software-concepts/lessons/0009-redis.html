1O modelo mental (3 cartões)The mental model (3 cards)

RAM, não discoRAM, not disk

Tudo vive em memória. Um GET custa ~1 ms — sem busca em disco, sem plano de consulta. É uma tabela hash gigante e rápida.Everything lives in memory. A GET costs ~1 ms — no disk seeks, no query plans. It's one giant, fast hash table.

Estruturas, não só stringsStructures, not just strings

Além de string: hash (objeto), list (fila), set (único), sorted set (ranking com nota). Operações atômicas: INCR, SADD, ZADD — o servidor é single-threaded, sem corrida.Beyond strings: hash (object), list (queue), set (uniqueness), sorted set (scored ranking). Atomic operations: INCR, SADD, ZADD — the server is single-threaded, no races.

TTL por chaveTTL per key

Cada chave pode expirar sozinha (SETEX user:42 60). O dado quente fica; o frio sai sem ninguém rodar limpeza. Cache morre sozinho.Every key can expire on its own (SETEX user:42 60). Hot data stays; cold data leaves without anyone running cleanup. Caches die on their own.

3A memória ao vivo: TTL, hit e missMemory live: TTL, hit and miss

Os cartões são a memória do Redis: cada chave com a barra de TTL derretendo. Clique em GET até ver um hit (~1 ms) — e espere o TTL de user:42 ou de cart:ana expirar para sentir o miss (~120 ms + repovoamento).The cards are Redis's memory: each key with its melting TTL bar. Click GET until you see a hit (~1 ms) — and wait for user:42's or cart:ana's TTL to expire to feel the miss (~120 ms + refill).

Repare na simetria com a lição de SQS: o miss é o “preço” que você paga de vez em quando para os hits ficarem baratos. A pergunta de arquitetura é sempre: hit rate alta o suficiente para valer a RAM?Notice the symmetry with the SQS lesson: the miss is the “price” you pay occasionally so hits stay cheap. The architecture question is always: is the hit rate high enough to be worth the RAM?

4O que derruba todo mundoWhat trips everyone up

Expirar ≠ ser evitado. O TTL leva a chave embora quando o tempo acaba. Mas se a memória encher antes, a política de eviction decide quem sai (padrão comum: allkeys-lru — a chave menos usada recentemente, mesmo com TTL no futuro). Chave sumiu “antes da hora”? Não é bug — é falta de RAM.Expiring ≠ being evicted. The TTL removes the key when time runs out. But if memory fills up first, the eviction policy picks the victim (a common default: allkeys-lru — the least recently used key, even with TTL left). Key vanished “early”? Not a bug — you ran out of RAM.

Segundo susto: o cache stampede. Uma chave popular expira e 500 requisições dão miss juntas — 500 leituras idênticas no banco ao mesmo tempo. Primeira defesa: TTL com jitter (60s ± aleatório) e repovoamento único; o resto é lição de outro dia.Second scare: the cache stampede. A popular key expires and 500 requests miss together — 500 identical DB reads at once. First defense: TTL with jitter (60s ± random) and single-flight refill; the rest is a lesson for another day.

Redis não é fonte da verdade. Ele tem persistência (RDB snapshot, AOF log) — mas o contrato honesto do cache é: pode cair, pode perder calor, e o sistema continua. A verdade vive no banco; o Redis é o atalho.Redis is not the source of truth. It has persistence (RDB snapshots, AOF log) — but the honest cache contract is: it can crash, it can lose warmth, and the system survives. Truth lives in the database; Redis is the shortcut.
