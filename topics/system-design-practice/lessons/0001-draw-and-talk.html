1O loop de performanceThe performance loop

Não tente desenhar e explicar tudo ao mesmo tempo. Use um ritmo fixo: cada traço responde a uma pergunta.Do not try to draw and explain everything at once. Use a fixed rhythm: every stroke answers one question.

Frase de controle:Control sentence: “Vou desenhar o caminho principal primeiro; depois escolho um gargalo para aprofundar.”“I’ll draw the happy path first; then I’ll choose one bottleneck to deep-dive.”

2O desenho mínimo viávelThe minimum viable drawing

Para os primeiros cinco minutos, limite-se a cinco elementos. Complexidade precoce é silêncio disfarçado.For the first five minutes, limit yourself to five elements. Premature complexity is silence in disguise.

① ClienteClient

Quem inicia? Web, mobile, outro serviço?Who initiates? Web, mobile, another service?

② EntradaEntry

DNS, CDN, load balancer ou API gateway.DNS, CDN, load balancer, or API gateway.

③ ComputeCompute

Um serviço. Não uma frota de microsserviços.One service. Not a fleet of microservices.

④ EstadoState

DB, cache, object storage—só o que o fluxo usa.DB, cache, object storage—only what the path uses.

Exemplo: encurtador de URLExample: URL shortener 
Browser ──> API ──> URL service ──> DB
                              └──> cache (read path)

fala: “Escreve no DB; leituras quentes podem evitar o DB via cache.”say: “Writes go to the DB; hot reads can bypass it through cache.”

3A fala que acompanha o traçoThe narration that follows the stroke

“DesenhoDraw → intençãointent → limiteboundary.”

  • “Adiciono um cache para reduzir latência de leitura.”“I’m adding a cache to reduce read latency.”
  • “O custo é invalidação; aceito consistência eventual para este caso.”“The cost is invalidation; I accept eventual consistency here.”
  • “Se o cache cair, a leitura volta ao DB—mais lenta, mas funcional.”“If cache fails, reads fall back to the DB—slower, but functional.”

Isso torna seu raciocínio observável. O entrevistador pode corrigir uma hipótese antes de você investir dez minutos no ramo errado.This makes your reasoning observable. The interviewer can correct an assumption before you spend ten minutes on the wrong branch.
