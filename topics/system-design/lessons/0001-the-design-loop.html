Quer seja numa entrevista de 45 min ou num design doc de 2 semanas, você percorre estes cinco estágios. O segredo é a ordem: clarificar antes de esboçar.Whether it's a 45-minute interview or a 2-week design doc, you move through these five stages. The trick is the order: clarify before you sketch.

1 · Clarificar1 · Clarify

O que o sistema faz (funcional) e quão bem (não-funcional). Nunca desenhe sem isso.What the system does (functional) and how well (non-functional). Never design without it.

2 · Estimar2 · Estimate

Escala: usuários, leituras/escritas, dados, banda. Números orientam os blocos.Scale: users, reads/writes, data, bandwidth. Numbers drive the blocks.

3 · Esboçar3 · Sketch

Arquitetura de alto nível: clientes, serviços, dados, filas. Apenas o esqueleto.High-level architecture: clients, services, data, queues. Just the skeleton.

4 · Aprofundar4 · Deep-dive

Mergulhe no componente mais interessante: esquema de dados, algoritmo, escala.Zoom into the most interesting component: data schema, algorithm, scaling.

5 · Negociar (o tempo todo)5 · Trade off (all the time)

Cada escolha tem um custo. Nomeie a tensão e justifique com números — não com voto.Every choice has a cost. Name the tension and justify with numbers — not a vote.

O erro nº 1: pular para caixinhas e setas antes de saber o que o sistema precisa entregar. Você desenha a coisa errada — rápido.The #1 mistake: jumping to boxes and arrows before you know what the system must deliver. You build the wrong thing — fast.

2Requisitos: o que faz vs. as “forças”Requirements: what it does vs. the “forces”

Requisitos funcionais = comportamento. Requisitos não-funcionais = os atributos de qualidade, as forças que vão puxar o design em direções opostas.Functional requirements = behavior. Non-functional requirements = the quality attributes, the forces that pull the design in opposite directions.

3Estime antes de desenharEstimate before you design

Números redondos bastam. Eles decidem se você precisa de um cache, um shard, ou nada disso. Decore a tabela de latências: memória ~100 ns, SSD ~100 µs, rede de datacenter ~0,5 ms.Round numbers are enough. They decide whether you need a cache, a shard, or none of it. Memorize the latency table: memory ~100 ns, SSD ~100 µs, datacenter network ~0.5 ms.

4Toda escolha é uma balançaEvery choice is a seesaw

Não existe bala de prata, só tensões. Nomeie o eixo e diga qual lado você escolheu — e por quê.There's no silver bullet, only tensions. Name the axis and say which side you picked — and why.

⇆

Latency ↔↔ Throughput

Bufferiza para throughput; responde imediato para latência.Batch for throughput; answer now for latency.

⇆

Consistency ↔↔ Availability

O eixo do CAP. Bancos: consistente; caches: disponível.The CAP axis. Databases: consistent; caches: available.

⇆

Cost ↔↔ Reliability

Cada 9 a mais de disponibilidade custa ~10×. Defina o SLO primeiro.Each extra nine of availability costs ~10×. Set the SLO first.

⇆

Coupling ↔↔ Autonomy

Serviços separados ganham autonomia, perdem simplicidade.Split services for autonomy, lose simplicity.

Reflexo de entrevista: ao propor algo, diga sempre “e o custo é…”. Isso é o que diferencia júnior de sênior.Interview reflex: whenever you propose something, always add “and the cost is…”. That's what separates junior from senior.

  3. 3
    Sketch: cliente → API → (cache) → armazenamento KV → redirecionamento 301.client → API → (cache) → KV store → 301 redirect.

  5. 5
    Trade off: 301 (cacheável, barato) vs 302 (rastreável); consistência eventual do cache.301 (cacheable, cheap) vs 302 (trackable); eventual cache consistency.
