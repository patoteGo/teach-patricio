All Core Interactive Sessions Customization Models Modes & Trust

Pi

Core

The minimal terminal coding harness itself — the host program that loops a model over a handful of file/shell tools. Not an IDE, not an agent framework.

Harness

Core

The layer that orchestrates the model↔tool loop and stores the session. Pi's defining identity: a thin host you extend, rather than a fat app you configure.

Turn

Core

One model response plus any tool calls it makes — the body of the agent loop. Turns repeat until the model replies in plain text and stops calling tools.

see Lesson 1 · The Core Loop

Agent loop

Core

The reasoning cycle: agent_start → turns → agent_end → agent_settled. "Settled" means no auto-retry, compaction, or follow-up remains.

Tool

Core

A capability the model can call. Built-ins plus any registered by extensions. The model decides when to call them; Pi decides how they run.

Built-in tools

Core

read, bash, edit, write (on by default) + grep, find, ls (opt-in). Scope the set with --tools / --exclude-tools.

Steering message

Interactive

Queued with Enter while the agent works. Delivered after the current assistant turn finishes its tool calls — lets you redirect a live loop without blocking it.

Follow-up message

Interactive

Queued with Alt+Enter. Delivered only after the agent finishes all work. Use for "and then also do X."

Thinking level

Interactive

Model reasoning depth: off · minimal · low · medium · high · xhigh · max. Shift+Tab cycles it. Editor border color reflects the current level.

/reload

Interactive

Reload extensions, skills, prompts, themes, and context files without restarting the session. Your feedback loop while authoring customizations.

Inline bash

Interactive

!command runs and sends output to the model; !!command runs without sending. Your shell, inline, anytime.

@file

Interactive

Type @ in the editor to fuzzy-search and attach project files. CLI equivalent: pi @file.md "…".

External editor

Interactive

Ctrl+G opens externalEditor / $VISUAL / $EDITOR (or nano) for long prompts.

Session

Sessions

The conversation as a JSONL file with a tree structure (each entry has id + parentId). Auto-saved under ~/.pi/agent/sessions/ by working directory.

Branching

Sessions

In-place session forks via the tree structure — one file holds every branch. No "undo", just navigate to any earlier point and continue.

/tree

Sessions

Navigate the session tree; jump to any point and keep working. Open fast with Esc Esc. Label bookmarks with Shift+L.

/fork

Sessions

Create a new session file from a previous user message on the active branch. Good for "what if I'd asked it differently".

/clone

Sessions

Duplicate the current active branch into a new session file at the current position, keeping full history.

Compaction

Sessions

Lossy summarization of older messages to free context. Full history is never lost — it stays in the JSONL; revisit via /tree.

/compact

Sessions

Trigger compaction manually, with optional custom instructions (/compact focus on recent changes). Auto-compaction is on by default.

Extension

Customization

TypeScript module extending Pi: custom tools, commands, event handlers, UI. Loaded via jiti — no compile step. The deepest power surface.

Skill

Customization

On-demand capability package (SKILL.md) following the Agent Skills standard. Only the description is always in context — full instructions load on demand (progressive disclosure).

Prompt Template

Customization

Reusable prompt as a .md file; expand with /name. Supports {{placeholder}} interpolation.

Theme

Customization

Visual theme (dark / light built in). Hot-reloads: edit the file, changes apply instantly.

Pi Package

Customization

Bundle of extensions/skills/prompts/themes shared via npm or git. Install with pi install npm:@foo/bar. Runs with full system access — review first.

Context files

Customization

AGENTS.md (or CLAUDE.md) auto-loaded at startup from global, parent, and current directories and concatenated.

System prompt

Customization

Base model instructions. Replace via .pi/SYSTEM.md; append (don't replace) via APPEND_SYSTEM.md.

MCP

Customization

Model Context Protocol — the standard Pi deliberately does not use. Build a CLI + skill instead, or add MCP via an extension.

why?

Provider

Models

The LLM backend: Anthropic, OpenAI, Google, OpenRouter, etc. Authenticate via subscription (/login) or API key.

Model

Models

The specific LLM selected (e.g. claude-sonnet-4). Ctrl+L opens the selector; --model provider/id on the CLI.

Scoped models

Models

The subset enabled for Ctrl+P cycling. Set via /scoped-models or the --models flag.

/login

Models

Manage provider credentials — pick a subscription (Claude Pro/Max, ChatGPT Plus/Pro, Copilot) or paste an API key. /logout clears them.

Interactive mode

Modes

Default TUI mode — you converse with Pi in the terminal. Everything in this glossary's "Interactive" category assumes this mode.

Print mode

Modes

pi -p "…" — one-shot: print the response and exit. Reads piped stdin: cat file | pi -p "summarize".

JSON mode

Modes

pi --mode json — emit every event as a JSON line. For building pipelines and observability on top of Pi.

RPC mode

Modes

pi --mode rpc — strict LF-delimited JSONL over stdin/stdout, for non-Node.js process integration.

SDK

Modes

Embed Pi in your own app: createAgentSession(). Out of current scope — revisit after interactive mastery.

Project trust

Modes

Decision to load a project's .pi resources (settings, extensions, skills). Saved in ~/.pi/agent/trust.json via /trust. Security boundary.

pi install

Modes

Install a package (npm: or git: source). -l for project-local. Manage with pi list, pi config, pi update.

pi.dev

Modes

Canonical docs site — pi.dev/docs/latest. The source of truth this glossary mirrors.
