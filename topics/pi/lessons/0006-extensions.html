⬡ Lesson 06 · The deepest surface

Extensions:
program Pi itself.

Skills give the model instructions; extensions give Pi code. A TypeScript module that can add tools, register commands, and hook every event in the agent loop — block a tool, rewrite a result, inject context, build UI. This is where Pi stops being a tool and becomes a platform.

↑ Mission · prev: Lesson 5 · Skills · ref: Glossary

1What an extension is

One TypeScript file with a default-exported factory. Pi loads it via jiti — no compile, no build step. Edit, /reload, done. 

import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";

export default function (pi: ExtensionAPI) {
  // subscribe to events · register tools/commands/shortcuts/flags/UI
  pi.on("session_start", (_e, ctx) => ctx.ui.notify("loaded!", "info"));
}

🔧 Custom tools

Register capabilities the LLM calls — pi.registerTool(). Anything you can code.

📣 Commands & UI

/mycmd, status lines, widgets, full TUI components via ctx.ui.

🛡️ Event hooks

Intercept anything: block a tool, modify a result, inject context, customize compaction.

The dividing line: a skill tells the model what to do (Markdown the model reads). An extension changes what Pi is (code Pi runs). Reach for a skill first; reach for an extension when you need code.

Source: Pi docs · Extensions · imports: @earendil-works/pi-coding-agent, typebox, @earendil-works/pi-ai, @earendil-works/pi-tui.

2The event lifecycle — hook anything

Pi emits events at every stage of the agent loop. Each is a place you can plug in. The ones in red can block or mutate — those are the power hooks.

Two hooks do 80% of the work: tool_call (before a tool runs — block or mutate) and tool_result (after — modify the result). Master those two and you can build safety gates, audit logs, redaction, and more.

3Custom tools — new capabilities

Give the model a verb it didn't have. Define params with typebox; return { content, details }. 

pi.registerTool({
  name: "deploy",
  label: "Deploy",
  description: "Deploy the current branch to staging.",
  parameters: Type.Object({
    env: StringEnum(["staging", "prod"] as const),
  }),
  async execute(toolCallId, params, signal, onUpdate, ctx) {
    onUpdate?.({ content: [{ type: "text", text: "building…" }] });
    const out = await runBuild(params.env);
    return {
      content: [{ type: "text", text: `deployed to ${params.env}` }],
      details: { env: params.env, log: out },
    };
  },
});

Tools appear instantly. registerTool() works mid-session — no /reload needed. Add promptSnippet (one-liner in "Available tools") and promptGuidelines (when to use it) so the model reaches for it at the right time.

4Interception — the safety gate

The canonical power pattern: catch a dangerous command before it runs and ask the human. tool_call can return { block: true } or mutate event.input. 

// ~/.pi/agent/extensions/safety.ts
import { isToolCallEventType, type ExtensionAPI } from "@earendil-works/pi-coding-agent";

export default function (pi: ExtensionAPI) {
  pi.on("tool_call", async (event, ctx) => {
    if (!isToolCallEventType("bash", event)) return;
    if (/\brm\s+-rf\b/.test(event.input.command)) {
      const ok = await ctx.ui.confirm(
        "Dangerous command",
        `Allow: ${event.input.command}?`
      );
      if (!ok) return { block: true, reason: "Blocked by user" };
    }
  });
}

Test instantly: pi -e ./safety.ts loads it for one run. Or drop it in ~/.pi/agent/extensions/ and /reload.

Same hook, mutate instead: prepend event.input.command = "source ~/.profile\n" + event.input.command to fix your shell env on every command.

5The ctx surface

Every handler gets a ctx. These are the methods you'll reach for constantly.

ctx.ui

notify · confirm · select · input (dialogs), setStatus · setWidget (footer/widgets), custom() (full TUI component).

ctx.sessionManager

Read-only session state: getEntries() · getBranch() · getLeafId().

ctx.signal

The agent abort signal — pass to fetch()/LLM calls so Esc cancels them.

ctx.model · ctx.thinkingLevel · ctx.scopedModels

Active model + reasoning level + the Ctrl+P cycle set.

ctx.getContextUsage() · ctx.compact()

Read the context budget; trigger compaction programmatically.

ctx.cwd · ctx.mode · ctx.hasUI

Working dir; tui|rpc|json|print; guard dialogs with hasUI.

6Where they live & reload

Same trust model as Lesson 4 — project-local extensions run with full permissions and need trust. 

# global (all projects)
~/.pi/agent/extensions/my-ext.ts
~/.pi/agent/extensions/my-ext/index.ts   # multi-file

# project-local (needs trust)
.pi/extensions/*.ts

# quick test · load once
pi -e ./safety.ts                         # -e = --extension

# reload after editing (auto-discovered locations only)
/reload

Defer heavy resources. Don't start processes/sockets/watchers from the factory — it may run without a session. Start them in session_start, clean up in session_shutdown.
