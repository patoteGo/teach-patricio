⬡ Lesson 04 · Configuration

Teach Pi
your codebase.

Out of the box Pi knows nothing about your project — no stack, no conventions, no commands. Three plain files fix that. This is the cheapest, highest-leverage customization in all of Pi: write Markdown, change behavior.

1The three levers

Each shapes Pi's behavior at a different layer. Know which lever does what and you stop fighting the tool.

📄

AGENTS.md

Context. Instructions, conventions, commands the model reads. Concatenated from global → parents → current.

most-used lever
🧠

SYSTEM.md

Prompt. Replace (SYSTEM.md) or extend (APPEND_SYSTEM.md) the base system prompt.

rarely needed
⚙️

settings.json

Knobs. Default model, thinking, compaction, themes, resource paths. Project overrides global.

behavior config

90% of the value is AGENTS.md. Before reaching for a skill or extension, ask: "could a paragraph of context fix this?" Usually, yes.

2AGENTS.md — the primary lever

Pi loads AGENTS.md (or CLAUDE.md) at startup from three places — and concatenates every match into the system prompt.

Concatenate, not override. Unlike settings, multiple AGENTS.md files stack. Put shared style globally, repo conventions at the repo root, and module quirks in subdirs — all compose. Disable everything with --no-context-files (-nc).

What to actually put in it

# AGENTS.md  — commit this to your repo

## Stack
TypeScript · Node 20 · Hono · Postgres (Drizzle ORM)

## Commands
- npm test           # run after every change
- npm run lint      # biome
- npm run db:migrate

## Conventions
- Never edit src/generated/ — auto-generated.
- Prefer early returns; avoid nested ternaries.
- API responses use snake_case.

## Gotchas
- Tests need docker compose up -d postgres first.

Source: Pi docs · Context Files.

3The system prompt — replace vs append

For when AGENTS.md isn't enough and you need to change how Pi instructs the model, not just add context.

🔴 SYSTEM.md — replace

.pi/SYSTEM.md (project) or ~/.pi/agent/SYSTEM.md (global). Throws away Pi's default system prompt. Context files + skills are still appended.

Use only if you genuinely need a custom persona or strict guardrails.

🟢 APPEND_SYSTEM.md — extend

APPEND_SYSTEM.md adds to the default prompt without replacing it. The safe default for extra rules.

CLI equivalents: --system-prompt "…" / --append-system-prompt "…".

Default to append. Replacing the system prompt discards Pi's careful defaults — reach for it only when you have a specific reason. Nine times out of ten, AGENTS.md + APPEND_SYSTEM.md is the right pair.

4settings.json — project overrides global

Where AGENTS.md is content for the model, settings are behavior for Pi. Two files, one rule: project wins, nested objects merge.

The handful worth knowing

defaultProvider · defaultModel · defaultThinkingLevel

Pin your everyday model + reasoning depth so every session starts right.

enabledModels

Glob patterns for Ctrl+P cycling: ["claude-*", "gpt-4o"].

treeFilterMode · doubleEscapeAction

Default /tree filter; what Esc Esc opens (tree/fork).

compaction · branchSummary

Tune context survival (Lesson 3).

externalEditor

e.g. "code --wait" for VS Code on Ctrl+G.

packages · extensions · skills · prompts · themes

Resource discovery paths (globs, ! exclude). Feeds Lesson 5+.

Source: Pi docs · Settings · edit directly or via /settings.

5Trust — the security boundary

Anything in .pi/ can run code (extensions execute; skills can instruct the model to do anything). So Pi gates project-local resources behind a trust decision.

Interactive

On startup, Pi asks before loading .pi/ for a folder with no saved decision. Save your answer with /trust → writes ~/.pi/agent/trust.json (restart to apply).

Non-interactive

-p / --mode json / rpc can't prompt, so they fall back to defaultProjectTrust: "ask" (default) · "always" · "never". Override one run with -a / -na.

Why it matters: .pi/extensions/*.ts and installed packages run with your full permissions. The trust prompt is the one gate between "I cloned a repo" and "arbitrary code just ran." Review project-local extensions before trusting — same hygiene as npm install.

Source: Pi docs · Project Trust.

6Copy-paste starter

Drop these two files in a repo and Pi immediately behaves better — no extensions, no packages. 

# .pi/settings.json
{
  "defaultThinkingLevel": "medium",
  "enabledModels": ["claude-sonnet-*", "gpt-4o"],
  "treeFilterMode": "labeled-only",
  "doubleEscapeAction": "tree",
  "compaction": { "keepRecentTokens": 24000 }
}
# + an AGENTS.md at the repo root (see §2 template)

Commit both. AGENTS.md + .pi/settings.json in the repo means every teammate's Pi (and yours on another machine) starts identical. That's configuration-as-documentation.
