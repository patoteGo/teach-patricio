⬡ Lesson 05 · The power surface

Skills:
capability on demand.

A skill is a folder of instructions + helper scripts that Pi loads only when relevant. It's the laziest, most portable way to program Pi — no build step, no framework, works in Claude Code and Codex too. This is where the tool becomes yours.

↑ Mission · prev: Lesson 4 · Context files · ref: Glossary

1The big idea: progressive disclosure

You can have dozens of skills without bloating context. At startup Pi loads only each skill's name + description. The full SKILL.md is read on-demand, the moment a task matches. Cheap to keep around; loaded only when earned.

Why this matters: the description is the routing key. Pi decides "load this skill?" purely from that one field. Write it like a trigger — what it does and when to use it — and the model finds it automatically. Vague description = a skill that never fires.

Source: Pi docs · Skills · follows the Agent Skills standard (portable to Claude Code, Codex, …).

2Anatomy of a skill

A directory with a SKILL.md. Everything else is freeform — scripts, references, templates, whatever the task needs. 

my-skill/
├── SKILL.md            # required: frontmatter + instructions
├── scripts/
│   └── process.sh       # helper the model calls via bash
├── references/
│   └── api-reference.md # detailed docs, loaded only if needed
└── assets/
    └── template.json    # static files

Reference paths are relative to the skill dir. In SKILL.md write See [the API ref](references/api-reference.md) — Pi resolves it. The model loads deep references lazily, keeping context lean.

3The SKILL.md format

Frontmatter (name + description required) + a Markdown body of instructions. That's the whole contract.

✅ Good description

"Extracts text and tables from PDF files, fills PDF forms, and merges PDFs. Use when working with PDF documents."

Specific triggers → reliable auto-load.

❌ Poor description

"Helps with PDFs."

Too vague → the model never reaches for it.

Frontmatter fields

name ·required

1–64 chars, lowercase a-z 0-9 -, no leading/trailing or consecutive hyphens. Need not match the folder name.

description ·required

≤1024 chars. The routing key. Missing it → skill won't load at all.

disable-model-invocation

true hides it from auto-load; users must call /skill:name explicitly.

allowed-tools · license · compatibility · metadata

Optional. allowed-tools pre-approves a tool set (experimental).

Validation is lenient: bad names warn but still load; only a missing description silently drops the skill.

4Where they live

Drop a folder in any of these and Pi finds it. Project locations load only after the project is trusted.

🌍 Global (every project)

~/.pi/agent/skills/
~/.agents/skills/

Your personal toolkit, always available.

📦 Project (per-repo)

.pi/skills/
.agents/skills/ (cwd + ancestors → git root)

Commit with the repo → shared with the team.

🔧 Other sources

Packages (skills/ or pi.skills), the settings skills array, and --skill <path> (repeatable, works even with --no-skills).

🔀 Other harnesses

Reuse Claude Code / Codex skills directly:

"skills": ["~/.claude/skills", "~/.codex/skills"]

Discovery quirk: in ~/.pi/agent/skills/ & .pi/skills/, a bare root .md counts as a skill too; in ~/.agents/skills/ & project .agents/skills/, root .md files are ignored — use a SKILL.md folder.

5How to fire one

Two ways. Let the model decide (default), or force it.

Automatic

You just ask normally. The model matches your request against skill descriptions and reads the right SKILL.md. Invisible to you.

Forced — /skill:name

/skill:commit loads & runs it. Pass args: /skill:pdf-tools extract invoice.pdf (appended as User: …). Toggle these commands via enableSkillCommands.

6A real skill, end to end

Drop this in ~/.pi/agent/skills/commit/ and you've extended Pi. It drafts a Conventional Commit from staged changes. 

commit/SKILL.md
---
name: commit
description: Draft and create a Conventional Commit from staged changes. Use when the user says "commit", "commit this", or wants to save staged work with a clear message.
---

# Commit

## Convention
`type(scope): summary` — type ∈ feat | fix | refactor | docs | test | chore.
Summary ≤ 72 chars. Body explains the why, not the what.

## Steps
1. Run `./scripts/diff-stat.sh` to see what's staged.
2. `read` the staged diff if you need detail.
3. Draft summary + short body.
4. Show the message; on approval run `git commit`.
5. Never commit secrets, .env, or node_modules.
commit/scripts/diff-stat.sh
#!/usr/bin/env bash
git diff --cached --stat

That's it. No build, no compile, no package step. Restart Pi (or /reload) and say "commit this" — the skill loads and the model follows your steps.

Cheate-code: just ask Pi to build the skill. "Make me a skill that…" — Pi writes the SKILL.md and scripts for you, then /reload.
