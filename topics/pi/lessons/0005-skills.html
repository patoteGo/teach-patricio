1A grande ideia: revelação progressivaThe big idea: progressive disclosure

Você pode ter dezenas de skills sem inchar o contexto. Na inicialização o Pi carrega apenas o nome + descrição de cada skill. O SKILL.md completo é lido sob demanda, no momento em que uma tarefa corresponde. Barato de manter por perto; carregado só quando merecido.You can have dozens of skills without bloating context. At startup Pi loads only each skill's name + description. The full SKILL.md is read on-demand, the moment a task matches. Cheap to keep around; loaded only when earned.

Por que isso importa: a description é o sinal de roteamento. O Pi expõe o nome + a descrição de cada skill; o modelo decide se lê o SKILL.md completo. Escreva a descrição como um gatilho — o que faz e quando usar — porque metadados vagos tornam o auto-carregamento não confiável.Why this matters: the description is the routing signal. Pi exposes each skill's name + description; the model decides whether to read the full SKILL.md. Write the description like a trigger — what it does and when to use it — because vague metadata makes auto-loading unreliable.

3O formato do SKILL.mdThe SKILL.md format

Frontmatter (name + description obrigatórios) + um corpo Markdown de instruções. Esse é o contrato inteiro.Frontmatter (name + description required) + a Markdown body of instructions. That's the whole contract.

✅ Boa descrição✅ Good description

"Extrai texto e tabelas de arquivos PDF, preenche formulários PDF e mescla PDFs. Use ao trabalhar com documentos PDF.""Extracts text and tables from PDF files, fills PDF forms, and merges PDFs. Use when working with PDF documents."

Gatilhos específicos → auto-carregamento confiável.Specific triggers → reliable auto-load.

❌ Descrição fraca❌ Poor description

"Ajuda com PDFs.""Helps with PDFs."

Muito vaga → o modelo nunca a procura.Too vague → the model never reaches for it.

Campos do frontmatterFrontmatter fields

name ·obrigatório·required

1–64 caracteres, a-z 0-9 - minúsculos, sem hífens iniciais/finais ou consecutivos. Não precisa coincidir com o nome da pasta.1–64 chars, lowercase a-z 0-9 -, no leading/trailing or consecutive hyphens. Need not match the folder name.

description ·obrigatório·required

≤1024 caracteres. A chave de roteamento. Sem ela → a skill não carrega de jeito nenhum.≤1024 chars. The routing key. Missing it → skill won't load at all.

disable-model-invocation

true a esconde do auto-carregamento; usuários devem chamar /skill:name explicitamente.true hides it from auto-load; users must call /skill:name explicitly.

allowed-tools · license · compatibility · metadata

Opcional. allowed-tools pré-aprova um conjunto de ferramentas (experimental).Optional. allowed-tools pre-approves a tool set (experimental).

A validação é branda: nomes ruins avisam mas ainda carregam; apenas uma descrição ausente descarta a skill silenciosamente.Validation is lenient: bad names warn but still load; only a missing description silently drops the skill.

# Commit

## Convenção## Convention
`type(scope): summary` — type ∈ feat | fix | refactor | docs | test | chore.
Resumo ≤ 72 caracteres. O corpo explica o porquê, não o quê.Summary ≤ 72 chars. Body explains the why, not the what.

## Passos## Steps
1. Rode `./scripts/diff-stat.sh` para ver o que está staged.1. Run `./scripts/diff-stat.sh` to see what's staged.
2. Dê `read` no diff staged se precisar de detalhe.2. `read` the staged diff if you need detail.
3. Rascunhe resumo + corpo curto.3. Draft summary + short body.
4. Mostre a mensagem; com aprovação rode `git commit`.4. Show the message; on approval run `git commit`.
5. Nunca commite secrets, .env, ou node_modules.5. Never commit secrets, .env, or node_modules.

#!/usr/bin/env bash
